# Security Policy

The Congress Watch team takes the security of our application, edge workers, and data very seriously.

## Supported Versions

We actively support and patch the latest version on the `main` branch.

| Version | Supported |
| ------- | --------- |
| main    | :white_check_mark: |

## Reporting a Vulnerability

If you believe you have found a security vulnerability in Congress Watch, please **do not open a public issue or discussion**.

Instead, please report it privately to our security team:

- **Email**: [security@trytir.com](mailto:security@trytir.com)
- **Subject Line**: `[Vulnerability Report] Congress Watch - <Brief Summary>`

### What to Include

Please include as much of the following information as possible to help us reproduce and resolve the issue quickly:

1. Type of issue (e.g., SSRF, SQL/D1 injection, secret leak, authentication bypass, edge worker denial of service).
2. Full paths to the affected source code or deployed endpoints.
3. Step-by-step reproduction instructions or a minimal proof-of-concept (PoC).
4. Any impact assessment or potential remediation suggestions.

### Response Timeline

- **Acknowledgment**: We aim to acknowledge receipt of all vulnerability reports within 48 hours.
- **Assessment & Fix**: We will assess the severity, keep you informed of our progress, and provide a coordinated release window.
- **Credit**: We will gladly credit you in our security advisories and release notes upon resolution (unless you prefer to remain anonymous).

Thank you for helping keep Congress Watch and its users safe!
